# parts-cli — Public CLI Rules

## Public/Private Boundary

This is the **public** CLI (`parts-cli`). The private CLI lives at `parts.sh/`.

### What this CLI supports

- PCB project type only (`ProjectTypePCB`)
- Template engine in `internal/templates/`: types, generator, embedded, registry
- Flags: `--revision` (default "A"), `--no-git`, `--kicad`, `--client-name`
- Embedded templates: README.md.tmpl, PARTS.md.tmpl, gitignore.tmpl, config.yaml.tmpl, LICENSE.md.tmpl, kicad_pro.tmpl, kicad_sch.tmpl
- LICENSE.md generation — always "Source Parts Inc." as DFM service provider
- KiCad project scaffolding
- Revision-qualified directory paths (`BOM/{{.Revision}}/`, `PCB/{{.Revision}}/`)
- Directory structures: ECO, IQC, DFT, SOP, DRC, ERC, BOM, PCB, Datasheets, Reports, Original_Files
- Git init via `exec.Command("git")` (not go-git)

### What this CLI must NEVER include

- `CLAUDE.md` template or generation — AI config is internal tooling
- DFM template (`DefaultDFMTemplate()`) — paid service feature
- Assembly template (`AssemblyTemplate()`) — paid service feature
- `go-git` library — keep using `exec.Command("git")`
- Workflow scaffolding, notification workflows, or API integration
- `--no-workflows`, `--update-workflows` flags
- Workflow embedded templates

### Shared with private CLI

The template engine is copied from private, not imported as a module. Keep these in sync:

- `ProjectMetadata` struct and builder methods
- `Generator` with `resolvePath()` path interpolation
- `Template`, `DirectorySpec`, `FileSpec` types
- PCB template directory/file definitions
- All shared embedded template files

## Sync Protocol

Changes flow **private -> public**. This repo receives updates, never originates shared features.

1. Private CLI implements the change
2. Relevant files are copied to `internal/templates/`
3. Private-only items are stripped (DFM/Assembly templates, CLAUDE.md, workflows)
4. Build verified: `go build ./...`
